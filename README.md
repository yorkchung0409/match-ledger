# 赛场账本 · 比赛记录

手机端的比赛记账本：记下打了什么比赛、拿了第几名、花了多少、拿回多少。

**线上地址：<https://yorkchung0409.github.io/match-ledger/>**

所有界面与逻辑都在根目录一个 `index.html` 里，零依赖、零构建，双击即可打开；`sw.js` + `manifest.json` 让它能装到主屏并离线使用。

## 装到主屏 / 离线

- **iPhone**：Safari 打开线上地址 → 分享 → 添加到主屏幕。之后从主屏图标启动，没有地址栏，状态栏也跟着主题走
- **安卓**：Chrome 打开 → 右上角菜单 → 安装应用 / 添加到主屏幕
- 装好后**断网也能记账**：页面本身被 Service Worker 缓存，数据本来就在本机。在牌桌上没信号时照样开、照样存，联网后下次打开自动更新到最新版
- 在线打开时走「先网络、失败再缓存」，所以不会因为缓存而用上旧版本

## 记什么

- 比赛名可复用：先把常打的比赛录进「比赛管理」，记账时直接选
- 比赛类型：**常规赛 / 卫星赛**。卫星赛赢的是更大比赛的门票，单独归类，详见下面「卫星赛与门票」
- 最终名次、收益、成本
- 时间用五列滚轮选择（年 / 月 / 日 / 时 / 分），日期自动联动
- 进圈档位：**圈外 / 进圈 / 进 FT**，记一笔时手动选，不按收益判断 —— 赏金赛圈外也能拿到淘汰奖励
- **币种**：每场单独选人民币或美元，两种桌子可以记在同一份账里
- **买入手数**：`×1` ~ `×5`，记这场一共买了几手（含 rebuy / add-on）
- **比赛人数**（可选）：这一场报名总人次，含重进 / rebuy。填了之后记录卡会显示 `32/420 · 前7.6%`，同比赛下一场自动带出上一次的人数
- **付费比例**（可选，在比赛管理里按赛事填一次）：这个赛事进钱圈的人数占比，决定首页进圈率下面那条基线

## 卫星赛与门票

卫星赛的奖品是更大比赛的门票（绑定本人、不能变现），不是现金。这类权益不能当收入记，否则首页净收益会虚高；票没用或过期时更是纯虚增。另外还有第二种票：**免费获赠的**，拿到它的过程根本没打过比赛。

**两条账分开**：

- 现金账：`净收益 = 收益 − 成本` 公式不变。`成本` 只表示自己掏的现金（含 rebuy），`收益` 只表示现金奖金。
- 门票账：`tickets[]` **一张票一条流水**，只在数据页「成绩结构 → 卫星赛」里出现。票**不是一场比赛**：不产生场次，不进净收益 / ROI / 进圈率 / FT 率 / 成绩结构 / 买入习惯 / 个人纪录。

一张票记：`source`（`sat` 打卫星赛赢的 / `gift` 免费获赠）、`face`（面值，**可留空**，为空存 `null`）、`cur`、`date`、`earnedIn`（哪场赢的，赠票为 `null`）、`usedIn`（**用在哪场**，未用为 `null`）、`note`。记录上的 `ticketCost` / `ticketWon` 保留为面值快照，另加 `ticketWonN`（这场赢了几张）和 `ticketUsedId`（这场用掉哪张）—— 张数与配对只认流水，不再拿记录条数相减。

记一笔时：收益类型选「赢门票」→ 填**每张面值**（可留空）和**张数**，保存时按张数生成 `sat` 票；成本来源选「门票」或「票 + 现金」→ **从列表里选中具体哪一张票**（赠票也能选），票面自动带出，现金成本只填自己掏的钱（rebuy / add-on）。免费获赠的票在数据页门票流水点「+ 登记赠票」，可一次登记多张、面值可留空；只有票、没打过卫星赛也能打开这个 tab。在「比赛管理」把比赛标成**卫星赛**，它就会单独归类，不混进常规赛的进圈率、成绩结构、买入习惯、个人纪录；但买入是真花钱，仍照记进净收益和走势。

台账口径：

| 项 | 定义 |
| --- | --- |
| 未用票数 | 流水里 `usedIn` 为空的张数；一张票多次 rebuy 也不会算错 |
| 已用票 | 点开能看到用在哪场，并能跳到那条记录 |
| 平均每张票花 | 卫星赛现金成本 ÷ **`sat` 票张数**；获赠的票单列，不进分子也不进分母 |
| 卫星赛胜率 | 赢票场次 ÷ 卫星赛场次，赠票不进 |
| 删记录 | 由这场赢到的票一并移除，这场用掉的票退回「未用」 |
| 删票 | 只影响台账，不动任何现金金额 |

例子：卫星赛 $50 赢一张 $500 主赛票；主赛用票进场、中途 rebuy $500 现金、最后赢 $2,000 现金。

| 记录 | 现金成本 | 门票台账 | 现金收入 | 净收益 |
| --- | --- | --- | --- | --- |
| 卫星赛 | $50 | — | $0（新增 1 张 $500 票） | −$50 |
| 主赛 | $500（rebuy） | 用掉那张 $500 票 | $2,000 | +$1,500 |

合计真金白银 **+$1,450**。票面 $500 只在台账里出现，不会在卫星赛当收入、又在主赛当成本。台账按全部记录算，不受「统计范围」影响，方便查「还有几张票没打」。

**老账本自动升级**：v3 及更早的备份打开时，赢票面值会补成 `sat` 票，用票但找不到更早未用票的会标成「获赠 · 来源未记」（免费送的票本来就打不了卫星赛）；按时间就近配对，**现金数字一个都不动**。配对不准可以在台账里删掉再登记。

## 买入手数（rebuy）

扑克比赛常有 rebuy，账上它和成本是一回事，所以：

- **成本填总投入**：买了 3 手就是 500 × 3 = 1500，直接写 1500。手数不是算钱用的，它只是个标签
- 在「比赛管理」给某个比赛填**一手买入**（可选）之后，记一笔选中它会自动带出成本，点 `×2` 就按两手算 —— 之后还能手动改；换到没设价钱的比赛时，自动带出的成本会被清掉，避免张冠李戴
- 手数能看出两件比率算不出来的事：**场均几手**，以及 **1 手 vs 2 手以上 的进圈率差**。后者要注意自选择偏差 —— 买多手的场次往往本来就是被打崩、被迫续命的局，只能当参考
- 老记录没有手数字段，一律按 1 手处理（读盘时自动补，不用手动迁移）

## 比赛人数与进圈基线

进圈率一直缺一个参照物：25% 到底算好还是算差？这两个字段就是来定标尺的。**它们只是分析维度，不进成本 / 收益 / 净收益 / ROI**，卫星赛一概不参与。

- **比赛人数** `records.fieldSize`：这一场的报名总人次（含 re-entry）。圈外也要填 —— 它是进圈率的分母，也是名次百分位的分母。
- **名次百分位** = 名次 ÷ 人数。420 人拿第 32 名 → `7.6%`，意思是赢了 92.4% 的人。**这个数在 100 人场和 1000 人场之间可以直接横比**，而「第 32 名」和「进圈了」都不具备这种可比性。
- **付费比例** `events.paidPct`：挂在**赛事**上（12 就是 12% 进钱圈），填一次作用于全部历史与未来 —— 读时 join，不写进记录快照，所以改赛事不用批量刷记录。
- **进圈基线** = 填了付费比例的那些场次取均值。首页进圈率下面那行会写 `进圈基线 12% · 高出 54.7pt`，并**标出来源**：
  - `赛事设定` —— 你填过，准的
  - `历史反推 · 偏低` —— 没填过时，取进圈记录里最差的一次名次百分位（≈ 钱圈边缘），**样本不足 20 场不显示**。反推一定低估，界面必须带这个标记，否则等于把低估当精确值用。
- **数据自检**：人数和付费比例都齐了以后，如果名次排在钱圈之外却标了「进圈」，保存时会提醒一句，**但不拦截** —— 档位还是你定（rebuy 不计人次之类的情况确实存在）。

老记录的人数保持 `null`（显示空白，不是 `0`），所有用到人数的统计分母都是「填了这个字段的场次」。历史人数是瞬时事实，回填不了；付费比例填几次就能盘活全部历史，这是两者的本质区别。

## 币种与汇率

- 记录卡永远显示**当时的原币**（美元桌就显示 `$`），因为那是这一场的事实
- 所有汇总（首页大数字、走势、成绩结构、比赛管理）按同一份汇率折成你选的**统计币种**；记录页 hero 和数据页顶卡都有 `¥ 人民币 / $ 美元` 切换，两处是同一个开关
- **账本里美元和人民币可以混着记**，但汇总只能有一个口径：先按汇率把不同币种折成你选的统计币种，再加总。记录卡仍各自显示当时的原币
- 统计币种**选过一次就记住**（存 `matchledger.cur`），下次打开还是它；没选过时按人民币起手。不去猜「账本是什么币种」—— 混着记的账本没有唯一答案，猜了反而让同一笔钱忽而 ¥ 忽而 $
- 金额被折算过时，成绩结构底部会写明「按 1$ ≈ ¥7.1 折算成人民币」并指向上面的切换 —— 免得以为算错了
- 汇率每天自动取一次（`open.er-api.com`，失败退 `frankfurter` 欧洲央行数据），取不到就沿用上次的值，不阻塞任何操作
- 也可以手动填：数据页 → 数据管理 → **美元汇率**。填你实际换汇的价往往比中间价更贴近真实成本
- 汇率只影响折算，**不改任何一条记录的原始金额**；备份 JSON 和导出的 CSV 都保留原币

## 找不到的口径都在 `?` 里

页面顶部右侧的 `?` 打开「口径与用法」，八组可折叠：一笔记录怎么填、这些数字怎么算、比赛人数与进圈基线、累计净收益与期初结余、美元与统计币种、走势图三种切法、档位与比赛管理、数据存在哪怎么带走。打开定位在第一组，展开过的组会留在下次打开。

页面上不再铺说明文字 —— 数据页底部只留一行「净收益 = 收益 − 成本」指路，比赛管理页原来那段说明也并进去了。本文档的「币种与汇率」「缺记录怎么算」「买入手数」三节与弹窗内容对应，改口径时两处一起改。

## 看什么

- **记录页**：累计净收益、场次、总投入、ROI、进圈率、FT 率，按月分组。**两个比率同分母**：进圈率 =（进圈 + 进 FT）÷ 常规赛场次，FT 率 = 进 FT ÷ 常规赛场次；卫星赛不进任何比率，有卫星赛时首页小字会写明分母。进圈率下面还有一行**进圈基线**（赛事设定的付费比例，没填就用历史反推并标出来），告诉你这个进圈率是高出随机水平还是低于它。记录卡副行会写 `32/420 · 前7.6%`。顶部可同时按比赛、盈亏（全部 / 盈利 / 亏损）、时间（年 / 月 / 日）筛选，三者叠加生效。**比赛筛选点开是一个可搜索的面板**（输入名字直接过滤，每行带这个比赛的场次数，点一行就生效并关闭），不是原生下拉。从数据页「成绩结构」点进来的档位筛选不占控件，会显示成筛选条下面一个可清除的 chip
- **数据页**：顶部「统计范围」按年 / 月 / 日圈定时间，下面的图、成绩结构、买入习惯、个人纪录全部跟着它走。**它和记录页的时间筛选是两份独立的状态**：各选各的、互不影响，在记录页筛 11 月不会把数据页也筛掉，反过来也一样
- **走势图有三种切法**，卡片右上角切换，选过的记在本地：

  | 切法 | 看什么 |
  | --- | --- |
  | **场次** | 一条线串起所有场次，画记账以来的累计净收益。每个点按名次档上色：**金 = 进 FT、品牌色 = 进圈、灰 = 圈外**，所以能看出钱是爆一场赚回来的还是稳定进圈攒出来的。记录超过 60 场时只标 FT 的点，免得糊成一片 |
  | **月度** | 每月一根柱，赚红亏绿；**没打的月份画一条浅色短横线**，看得出哪段时间断档。底部给最好 / 最差 / 月均，月均只按有记录的月份算 |
  | **比赛** | 按总净收益排序的横向条形，中线是 0，往右赚、往左亏，小字是场均和总成本。**点一行跳到记录页，只看这个比赛** |

- **成绩结构**：右上角切**常规赛 / 卫星赛**两个 tab（既没卫星赛、也没票时不显示切换；只有赠票也能打开）。
  - **常规赛**：圈外 / 进圈 / 进 FT 各自的场次占比与**场均净收益**。右边那个数是这一档的场均，不是这一档的总和 —— 6 场一共亏 $6.08，场均就是 −$1.01；想看总数在记录页把这一档筛出来看顶部。**三行都能点** —— 点了跳记录页、只留这一档，再点一次取消。想看「只看进圈的流水」从这里进，而不是把曲线的场次筛掉（筛掉圈外再画曲线，线必然一路向上，那是把结论先写好了）。
  - **卫星赛**：命中率、赢到票 / 没赢到各自的场次与**场均花**（每场平均掏出去的现金，赢了票也照算 —— 钱变成了票，所以这里不用净收益，免得看着像算错）。下面三格是全库门票流水汇总（赢到 / 已用 / 未用张数与面值），再往下是**门票流水面板**：未用票逐张列出来源、面值、日期，可删；已用票折叠起来，每张写明用在哪场并能跳过去；右上角「+ 登记赠票」补免费获赠的票（面值可留空）。脚注给**平均每张票花**（卫星赛现金成本 ÷ 赢到的票张数，赠票不进分母）。台账按全部记录算，不受统计范围影响。
- **比赛管理**：每个比赛的场次、进圈率、付费比例（填过才显示）、最好名次、成本与收益、场均净收益、场均手数

## 缺记录怎么算

记账之前的场次补不全，所以指标分两类口径：

- **比率类**（进圈率、FT 率、ROI、场均、单场极值、连胜连亏）只看「已记录的场次」。没记住的场次不补、也不猜 —— 缺样本只会让结果有偏，不会把公式算错。
- **累计金额**（累计净收益、走势曲线）会被缺记录影响。在数据页 → 数据管理 → **期初结余** 填一个「记账之前已经累计」的总数：它加进首页的累计净收益（和场次、ROI 无关），走势曲线仍然只画记账以来，卡片底部会把「记账以来 / 期初 / 合计」三个数摆出来对账，避免一个大额期初把后半段曲线压成平线。

期初结余会一起写进 JSON 备份。

## 数据与备份

所有数据只存在本机浏览器的 localStorage（键 `matchledger.v1`），不上传任何服务器。
换设备请先用「备份数据」导出 JSON，再到新设备「恢复」。也可以导出 CSV 自己算 —— CSV 共 12 列，含「人数」和「名次百分位」（`7.6%` 这样的字符串，Excel 直接读）。

读盘和恢复备份时都会先清洗一遍：不是对象的记录会被跳过并告知条数；时间不合法用创建时间补；成本/收益归一为非负数字；比赛名重复会重新分配 id。所以手改过的、被别的工具改坏的备份，多数能直接恢复进来，而不是让界面白屏。

**本机存储写不进去时不会假装成功**（配额满、隐私模式、站点数据被禁用）：页面顶部出现常驻警示条，所有「已保存 / 已删除 / 已恢复」提示都会带上「未存上本机」，并给一个直接导出当前数据的按钮。此时数据只在内存里，刷新会丢，先导出再排查。账本原文解析不了时会先另存到 `matchledger.v1.broken`；如果连这一步也写失败，就把原文留在内存里、**禁止任何自动写盘覆盖原键**，兜底页会如实说明「原文只在内存里」并允许先导出留底。

真遇到界面画不出来，会弹一张兜底页，给三个出口：**导出原始数据**（未经整理的原文字节）、**尝试修复**（清洗后重载）、**清空重来**。整份 JSON 解析失败时，原文还会另存一份到 `matchledger.v1.broken`，不会被下次保存覆盖。

### 数据格式（schema v5）

存进 localStorage 和写进备份的都是同一份结构，`schemaVersion: 5`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `records[].cost` / `.income` | number | 金额是数字，不是字符串；只表示**现金** |
| `records[].buyCount` | number | 买入手数（v1 叫 `buys`） |
| `records[].stage` | `out` / `itm` / `ft` | 圈外 / 进圈 / 进 FT |
| `records[].cur` | `CNY` / `USD` | 这一场的原币 |
| `records[].eventKind` | `regular` / `satellite` | 比赛类型快照，删比赛名后归类不漂 |
| `records[].ticketCost` / `.ticketWon` | number | 用掉 / 赢到的门票**面值快照**，不进净收益 |
| `records[].ticketWonN` | number | 这场赢到几张票（面值留空也照记） |
| `records[].ticketUsedId` | string \| null | 这场用掉哪张票，指向 `tickets[].id` |
| `records[].fieldSize` | number \| null | 本场报名总人次（含重进）；没填是 `null`，**不是 0** |
| `records[].itmBB` | number \| null | 进圈那一刻的筹码（BB），本期预留、界面没有入口 |
| `tickets[]` | array | 门票流水，一张票一条；不是比赛、不产生场次 |
| `tickets[].source` | `sat` / `gift` | 卫星赛赢到 / 免费获赠 |
| `tickets[].face` | number \| null | 票面值，**可留空** |
| `tickets[].cur` / `.date` | string | 票面币种、获票时间 |
| `tickets[].earnedIn` | string \| null | 哪场赢的（`gift` 为 `null`） |
| `tickets[].usedIn` | string \| null | **用在哪场**，未用为 `null` |
| `events[].kind` | `regular` / `satellite` | 常规赛 / 卫星赛 |
| `events[].unitPrice` | number \| null | 一手买入价（v1 叫 `buyin`），没设过是 `null` |
| `events[].paidPct` | number \| null | 该赛事进钱圈人数占比，整数百分比（`12` = 12%）；没填是 `null` |
| `openingBalance` | number \| null | 期初结余（v1 叫 `opening`） |
| `fxRate` / `fxUpdatedAt` / `fxSource` | number \| null | 汇率、取数时间、来源（v1 叫 `rate` / `rateAt` / `rateSrc`） |

v1 / v2 / v3 / v4 的备份可以直接恢复：读盘和导入时先做字段映射，再走清洗，最后写成 v5 —— 老文件不用手动改，缺的门票字段补 0、比赛类型补常规赛，v3 的赢票/用票面值按时间就近补出票流水，v4 及更早的记录缺人数补 `null`、比赛缺付费比例补 `null`，**所有金额一个数字都不变**。金额统一成 number 是为了让统计不必到处 parseFloat，空值统一成 `null` 是为了区分「没填」和「填了 0」。

## 主题

右上角调色盘切换。十一套主题（六浅五深）各自是一套完整的视觉语言，不只是换色板 —— 圆角、描边粗细、阴影类型、字体、背景纹理会一起变，所以手感完全不同：

| 主题 | 配色 | 形态 | 细节 |
| --- | --- | --- | --- |
| 账本 | 墨绿 + 暖白 | 20px 圆角、细描边、克制投影 | 无纹理，最安静 |
| 甜心 | 樱花粉 + 奶粉底 | 26px 圆角、胶囊按钮、圆形徽章 | 奶油波点、粉雾柔光 |
| 数据 | 深蓝 + 冷白 | 小圆角、几乎无投影、靠细线分层 | 坐标网格、等宽数字 |
| 暖阳 | 暖橘 + 米黄 | 大圆角、暖色投影 | 纸纤维斜纹、宋体标题 |
| 梦境 | 紫 + 淡紫 | 30px 超大圆角、渐变卡面 | 双团紫粉柔光 |
| 极简 | 纯黑白 | 直角、2px 黑边、4px 实心投影 | 等宽数字，没有渐变 |
| 夜账 | 墨绿黑 + 金 | 同账本 | 金的品牌色、深底浅字 |
| 深海 | 海军蓝黑 + 冷蓝 | 同数据 | 网格压暗，等宽数字 |
| 紫夜 | 深紫 + 淡紫 | 同梦境 | 紫雾光晕压在深底上 |
| 暗金 | 深棕黑 + 琥珀 | 同暖阳 | 纸纹压暗、宋体标题 |
| 炭黑 | 纯黑 + 白 | 同极简 | 反色：白边、白实心投影 |

深色那五套跟浅色一一对应，改的是底色、卡面、描边透明度、奖牌配色和阴影（深底上阴影几乎看不见，改成靠卡面亮一档分层）。品牌色在深底上必须提亮才看得清，所以另加了 `--on-brand` 管「品牌色上的文字」，否则金底上写白字就看不清了。

选择记在本地。

**启动图的底色也跟着主题走。** 安卓从主屏冷启动时那块纯色启动图，取的是 manifest 的 `background_color`，而 manifest 是浏览器在页面脚本跑起来之前就去取的 —— 页面改不到它。所以反过来做：页面按当前主题把 manifest 改写一份扔进 Cache，`sw.js` 拦到 `manifest.json` 请求时发这份。`<link rel="manifest">` 仍然指向同源的静态文件 —— 换成 `blob:` 实测也能解析，但安装判定会失去同源性，不值得为一张启动图冒这个险。首次访问、或浏览器不给 Cache API 时，退回仓库里那份浅色的 `manifest.json`。

iOS 不读 manifest 的这个字段，主屏启动想换底色只能塞 `apple-touch-startup-image` 静态图（一张固定尺寸的图片，跟不了主题），所以 iPhone 上仍是系统默认。
